FAIRNESS

We continuously change perception of online gambling by applying the revolutionary concept of provably fair gambling

OVERVIEW

BitKong is provably fair online cryptocasino. We introduce new generation of online casinos where players can be sure that results are not manipulated. BitKong’s verification procedure allows users to verify integrity of every bet

COMPONENTS

Server Seed is generated before Client Seed, ensuring that it is impossible to generate a Server Seed in favor of BitKong. In case, when user visits website for the first time it is impossible to prove that. Therefore, we advise users to randomize (change) Client Seed at first visit. At any particular moment current Server Seed is hidden from the user in order to prevent the result prediction. Instead, Hash (SHA256) of it is shown to guarantee that it will not be replaced by BitKong. Current Server Seed is used for all those bets, that are made after last Server Seed change (randomization) and is used until user decides to verify bet(s). Before user starts verification, he must also randomize current Server seed (to generate new one for the next bet(s)). After randomization is over, previous Server Seed will be opened and all bets made with that Server Seed can be checked. After that user doesn’t have to change the Client seed, but it is recommended do so. Server Seed is a random sequence of 64 symbols (numbers and letters) generated by a server. Client Seed is a random sequence of symbols specified by user (or generated by user’s browser). Nonce is a number of bets made with a certain Server Seed. This number is initially 0 and increases by one after each bet. After Server Seed is changed the Nonce is reset to 0. Row number of every ticket starts with 0 and increases by one with every row in a ticket.

GENERATING RANDOM OUTCOMES

Server seed, Client seed, Nonce, Ticket row number and Zero are used to create provably fair randomly generated outcomes. The output of random number generation is 32 random bytes, generated using the HMAC_SHA256(K,m) function. This function uses a given Server Seed (K) and a message (m). The message is created by concatenating Client seed, Nonce, Row number of the ticket and zero. m = "{client_seed}:{nonce}:{row_number}:0".

CREATING RESULTS

To create random results (events) that happen during the game a special formula is used. First four bytes of HMAC_SHA256(K,m) function’s result need to be converted into decimal values (0-255 each). First byte is divided by 256 (256 raised to power of 1), second byte is divided by 65,256 (256 raised to power of 2), third byte is divided by 16,777,216 (256 raised to power of 3), fourth byte is divided by 4,294,967,296 (256 raised to power of 4). The sum of the divisions is an equally distributed value greater than or equal to zero, but smaller than one. Final game result is calculated by multiplying that value with number of possible results (right and wrong) and taking only full part (floor) of that figure: 4 for Easy, 3 for Medium, 2 for Hard, 3 for Extreme, 4 for Nightmare. That number (the result) indicates the position of the winning cell in the row for Hard, Extreme, Nightmare modes and position of losing cell for the Easy and Medium modes.

BEST PRACTICE

Change Client Seed when you start playing at website. Copy and keep separately Server Seed hash and Client Seed. Don’t use one Server Seed for too many bets. Change Server Seed every once in a while and verify your bets (at least a few of them). After every randomization of Server Seed also randomize (change) Client Seed. When manually creating Client Seed do not use simple, easily predictable words. It is better to generate it with cryptographic random number generator, by clicking Refresh button at Fairness tab.
